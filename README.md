# VoIP SIP Analyzer

A simple web application that analyzes VoIP phone call captures (PCAP files) and automatically determines what happened during each call.

Upload a network capture from Wireshark, tcpdump, or another packet capture tool, and the system will identify whether calls were:

* ✅ Answered
* 📞 Missed
* ❌ Rejected
* 🚫 Cancelled
* ⚠️ Failed

Perfect for VoIP engineers, telecom administrators, support teams, and anyone troubleshooting SIP-based phone systems.

---

## What Does It Do?

VoIP SIP Analyzer reads SIP traffic from PCAP or PCAPNG files and converts complex packet data into an easy-to-understand call history.

Instead of manually inspecting hundreds of SIP messages in Wireshark, you can:

* Upload one or many capture files
* View all detected calls
* See call outcomes instantly
* Inspect SIP message flows
* Run validation tests
* Generate call statistics and analytics

---

## Features

### Call Detection & Classification

Automatically detects and classifies calls as:

| Status    | Description                                   |
| --------- | --------------------------------------------- |
| ANSWERED  | The call was successfully connected           |
| MISSED    | The phone rang but nobody answered            |
| REJECTED  | The call was actively declined or busy        |
| CANCELLED | The caller cancelled before ringing completed |
| FAILED    | The call failed because of an error           |

## Live Capture (v2.3.0)

Besides uploading PCAPs, the app can listen to a **SPAN/mirror port**, show calls as they happen,
record the audio and keep everything in the same database. It is an optional extra container:

```bash
docker compose --profile capture up -d --build
```

Set `CAPTURE_INTERFACE` in the root `.env` to the network card cabled to the mirror port.
Includes role-based access (admin / supervisor / user limited to their own extensions),
an audit log of recording playback and downloads, and automatic retention of old recordings.

See the full setup guide: [docs/LIVE_CAPTURE.md](docs/LIVE_CAPTURE.md).

## How It Works

The analyzer examines SIP signaling messages and determines the final outcome of each call.

Examples:

| SIP Flow                      | Result    |
| ----------------------------- | --------- |
| INVITE → 200 OK → BYE         | ANSWERED  |
| INVITE → 180 Ringing → CANCEL | MISSED    |
| INVITE → 486 Busy Here        | REJECTED  |
| INVITE → 603 Decline          | REJECTED  |
| INVITE → CANCEL               | CANCELLED |
| INVITE → 404 or 5xx Error     | FAILED    |

## Configuration

The application works out of the box with default settings.

### Call Audio (v2.2.0)

The app can rebuild call audio from the RTP in uploaded captures and let you play it back from a call's **Media** tab (caller on the left channel, callee on the right).

* Off by default. Enable with `SAVE_CALL_AUDIO=true` (Docker: set it in the **root** `.env`).
* Supports G.711 (PCMU/PCMA) only; other codecs are skipped without affecting call analysis.
* WAV files are stored in `data/recordings` and are deleted when you delete a call, a capture file, or use **Clear All Data**.
* Recording calls may carry legal obligations in your jurisdiction; only enable it for traffic you are permitted to record.

### Live Capture and Accounts (v2.3.0)

Live recording is on by default (`LIVE_RECORDING_ENABLED`), recordings are kept `RECORDINGS_RETENTION_DAYS`
(default 180) and optionally limited to `RECORDINGS_MAX_GB`. Login settings: `ADMIN_USERNAME`,
`ADMIN_PASSWORD`, `AUTH_SECRET`. All variables are listed in [docs/LIVE_CAPTURE.md](docs/LIVE_CAPTURE.md).

### Database

Default:

```text
SQLite
```

Data is stored locally and persists across container restarts.

Optional PostgreSQL support:

```env
DATABASE_URL=postgresql+asyncpg://USER:PASSWORD@HOST:5432/DBNAME
```

---

### SIP Parser

Default parser:

```text
Scapy
```

Benefits:

* Pure Python
* No tshark installation required
* Easy deployment
* Reliable SIP parsing

Optional:

```env
SIP_PARSER_BACKEND=pyshark
```

for environments that require tshark-based decoding.

## Limitations

* SIP traffic must be unencrypted
* TLS-encrypted SIP is not supported
* SRTP media streams are not analyzed
* Call audio reconstruction supports G.711 only
* Live capture needs unencrypted SIP/RTP and a mirror port; see [docs/LIVE_CAPTURE.md](docs/LIVE_CAPTURE.md)
* Upload limits can be configured through environment variables

## API Endpoints

Main API routes:

| Method | Endpoint           | Purpose                  |
| ------ | ------------------ | ------------------------ |
| GET    | /health            | Health check (public)    |
| POST   | /auth/login        | Sign in, returns a token |
| GET    | /auth/me           | Current user             |
| GET    | /capture/status    | Live capture status      |
| GET/POST/PATCH/DELETE | /users | User management (admin) |
| GET    | /audit             | Audit log (admin)        |
| POST   | /upload-pcap       | Upload a capture         |
| POST   | /upload-pcap/batch | Upload multiple captures |
| GET    | /calls             | List detected calls      |
| GET    | /calls/{id}        | View call details        |
| GET    | /calls/{id}/audio  | Reconstructed call audio (WAV) |
| GET    | /analytics         | Call statistics          |
| POST   | /replay-test       | Validation testing       |

All endpoints except `/health` and `/auth/login` need `Authorization: Bearer <token>`.

Interactive API documentation:

```text
http://localhost:8000/docs
```
